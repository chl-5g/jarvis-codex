# Jarvis 长期修改清单

这份清单记录用户已经确认的产品方向，作为后续实现的工作基线。完成状态以代码、日志和实际运行验证为准。

## 已确认方向

- 原生 Codex Voice 是默认语音和文字交互路径，本地语音只作为降级方案。
- 左下角按钮只负责麦克风静音/取消静音；不承担启动 Voice、发送文字或暂停任务。
- 左上角状态使用统一配置，显示 `WORKING` 等通用状态，不再写死 `Codex working`。
- 所有项目配置使用项目根目录 `config/*.json`，通过 `$PROJECT_PATH` 别名和 `config/paths.json` 读取绝对项目路径。
- 启动时不弹出一串权限请求；权限状态由统一权限管理器读取，能力第一次使用时按需申请。
- Rust 编排器继续拥有模型路由、记忆、Skills、工具、工作流、权限和统一事件流。
- 端侧模型自动检测，模型名不写死；可用时作为备用模型，不可用时继续使用 Codex。
- 端侧模型接入 LiteLLM/OpenAI 兼容网关时保留 reasoning 能力，简单请求可快速回答，复杂请求允许推理。
- `controller.py` 的本地 Whisper/Kokoro 能力只能通过受限 JSONL worker 接入，不能启动第二套 Jarvis、Codex、权限或 8082 服务。
- CipherPipe 能力接入 Jarvis，用于和其他 personal agent 建立对话与通信；不绕过 Jarvis 的权限和工具网关。
- 所有运行、事件和对话记录写入 `config/paths.json` 指定的日志目录。
- 系统能力通过统一工具注册表接入。用户提出任何可执行请求时，应自动完成：识别意图、检查能力、按需授权、调用工具、组织回答；不能在未尝试工具前直接说做不到。天气和位置只是验收例子。
- 摄像头、麦克风、屏幕录制、辅助功能、位置、网络访问等操作系统能力都遵循同一套按需权限管理，后续能力继续注册到这套机制。
- 不要求每个小任务单独提交，也不要求每个小改动都跑全量测试；在准备交付或声称完成前做必要验证。
- “完全访问”表示工具网关不限制用户明确授权的路径和命令；macOS root 与 TCC 权限仍由系统单独管理，不能用配置文件伪造。
